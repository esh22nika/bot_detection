# Model Paper Results — Verified Values from final_v03_corrected/

All values in this document are extracted from `final_v03_corrected/` artifacts
generated by `run_final_v03_corrected.py` on BotDriftBench v0.3 using an
**account-disjoint train/test split** (700 train accounts / 300 test accounts).
No v0.2 values are included. No values are invented.

Source files: `metrics.json`, `classifier_comparison.csv`, `degradation.csv`,
`drift_scores.csv`, `adaptation.csv`, `adaptation_summary.csv`,
`shap_ranking.csv`, `attribution.csv`, `feature_drift_validation.csv`.

## Table 2: Model Degradation Under Behavioral Drift

Static baseline model (seed 42, account-disjoint) evaluated per-window
on test accounts. F1 averaged over pre-drift (windows 0-4) and during-drift
(windows 5-15). Each scenario has ~25-32 test bots + ~150 test humans.

| Scenario | Pre-Drift F1 | During-Drift F1 | Abs F1 Drop | Ctrl-Adj |
|---|---|---|---|---|
| no_drift (control) | 0.589 | 0.540 | 0.049 | — |
| activity_drift | 0.507 | 0.451 | 0.057 | +0.008 |
| linguistic_drift | 0.599 | 0.570 | 0.029 | -0.020 |
| coordination_drift | 0.501 | 0.473 | 0.027 | -0.022 |
| network_drift | 0.399 | 0.349 | 0.050 | +0.001 |
| combined_drift | 0.438 | 0.400 | 0.038 | -0.011 |

Note: Per-scenario F1 is lower than aggregate baseline (0.81) due to class
imbalance in per-scenario evaluation (~25 bots vs ~150 humans per window).
Control-adjusted effects are mostly small, indicating degradation is
dominated by the evaluation setup rather than drift-specific effects.

Source: `degradation.csv`, `metrics.json`.

## Table 4: Adaptation Strategy Comparison (Account-Disjoint)

Per-scenario results using primary seed (42). Retrain uses train-account
data only; evaluate on test accounts. Test labels never used for training.

### Per-Scenario Detail

| Scenario | Strategy | Pre F1 | During F1 | Abs F1 Drop | Retrains |
|---|---|---|---|---|---|
| activity_drift | Static | 0.555 | 0.477 | 0.078 | 0 |
| activity_drift | Periodic | 0.555 | 0.524 | 0.032 | 4 |
| activity_drift | Drift-Aware | 0.555 | 0.525 | 0.030 | 13 |
| linguistic_drift | Static | 0.520 | 0.555 | -0.034 | 0 |
| linguistic_drift | Periodic | 0.520 | 0.574 | -0.054 | 4 |
| linguistic_drift | Drift-Aware | 0.520 | 0.568 | -0.048 | 13 |
| coordination_drift | Static | 0.443 | 0.409 | 0.034 | 0 |
| coordination_drift | Periodic | 0.443 | 0.457 | -0.014 | 4 |
| coordination_drift | Drift-Aware | 0.443 | 0.446 | -0.003 | 13 |
| network_drift | Static | 0.620 | 0.498 | 0.123 | 0 |
| network_drift | Periodic | 0.620 | 0.542 | 0.078 | 4 |
| network_drift | Drift-Aware | 0.620 | 0.547 | 0.073 | 13 |
| combined_drift | Static | 0.398 | 0.329 | 0.069 | 0 |
| combined_drift | Periodic | 0.398 | 0.402 | -0.004 | 4 |
| combined_drift | Drift-Aware | 0.398 | 0.391 | 0.007 | 11 |

### Aggregated Summary (Averaged Across All 5 Drift Scenarios)

| Strategy | Avg Abs F1 Drop | Avg Retraining Events |
|---|---|---|
| Static | 0.054 | 0.0 |
| Periodic | 0.008 | 4.0 |
| Drift-Aware | 0.012 | 12.6 |

**Interpretation**: Periodic retraining achieves the smallest average F1
drop (0.008 vs 0.012 for drift-aware) with fewer retraining events (4.0
vs 12.6). Both substantially outperform the static baseline (0.054).
The value of drift-aware adaptation is not F1 superiority but interpretable,
targeted response: each retraining is triggered by a detected shift and
accompanied by SHAP attribution identifying which features changed.

Source: `adaptation.csv`, `adaptation_summary.csv`.

## Framing Guidelines for the Paper

**Do use**:
- "account-disjoint train/test split"
- "empirically calibrated synthetic longitudinal benchmark"
- "train-population temporal drift monitoring"
- "targeted, interpretable response to detected distribution shifts"
- "SHAP-based feature attribution"
- "explanatory, not causal"
- "absolute F1 decrease"

**Do not use**:
- "real-time Twitter detection"
- "production-ready"
- "causal SHAP explanations"
- "ground-truth retweet labels"
- "first-ever" (without exhaustive literature verification)
- "state-of-the-art"
- "superior" (without statistical significance testing)
- "more efficient" (drift-aware uses 3.2x more retraining events)
- "relative F1 drop" / "percentage F1 drop" without clarification
